# 需求规格说明书 — 校园互助服务平台

**版本**：V1.0  
**日期**：2025年4月17日  
**团队**：佚名

---

## 1. 引言

### 1.1 目的

本文档旨在定义校园互助服务平台的功能性和非功能性需求，该平台允许学生发布和接单各类互助需求（快递代取、学习辅导、二手交易、组队匹配等），为后续设计、开发和测试提供依据。

### 1.2 范围

本平台面向在校大学生，提供任务发布与接单、信用评价、实时聊天、校内定位等功能。系统将包含移动端应用（微信小程序）和管理后台。

### 1.3 定义

| 术语 | 定义 |
|------|------|
| 发布者 | 提出互助需求的用户 |
| 接单者 | 接受并完成互助任务的用户 |
| 信用分 | 基于用户完成任务的记录计算的可信度分数 |

### 1.4 参考文献

- IEEE 830-1998 软件需求规格说明书标准
- 用户调研报告（docs/P1/调研报告.md）

---

## 2. 总体描述

### 2.1 产品视角

本产品为C2C校园互助平台，属于微信小程序生态，与校内身份认证系统（学号）集成。

### 2.2 用户特征

| 角色 | 特征 |
|------|------|
| 普通学生 | 发布需求或接单，关注便捷与信任 |
| 管理员 | 处理举报、审核异常行为 |

### 2.3 约束

- 开发周期：10周
- 技术栈：微信小程序 + 云开发
- 仅限本校学生使用（学号认证）

### 2.4 假设

- 用户拥有智能手机并能使用微信
- 校园网络环境稳定

## 3. 功能需求

### 3.1 用户认证模块

| 编号 | 需求描述 | 优先级 | 来源 |
|------|----------|--------|------|
| F-01 | 用户可通过学号+校园卡号进行实名认证 | Must | 人工补充 |
| F-02 | 认证后自动获取学院、年级信息 | Should | AI生成+人工修改（原为手动填写，改为自动获取） |
| F-03 | 支持微信一键登录 | Must | AI生成 |

### 3.2 任务管理模块

| 编号 | 需求描述 | 优先级 | 来源 |
|------|----------|--------|------|
| F-04 | 用户可发布互助任务（含标题、描述、报酬、地点、截止时间） | Must | AI生成 |
| F-05 | 用户可浏览所有待接单任务 | Must | AI生成 |
| F-06 | 用户可接单，接单后任务状态变更为“进行中” | Must | AI生成 |
| F-07 | 发布者可确认任务完成，接单者获得报酬 | Must | AI生成 |
| F-08 | 发布者/接单者可取消任务（需说明原因，扣除信用分） | Should | 人工补充 |
| F-09 | 接单者连续爽约2次以上，暂停接单权限7天 | Should | 人工补充 |
| F-10 | 任务支持分类筛选（快递代取、学习辅导、二手交易、组队匹配） | Must | AI生成 |

### 3.3 信用与评价模块

| 编号 | 需求描述 | 优先级 | 来源 |
|------|----------|--------|------|
| F-11 | 完成任务后双方可互评（1-5星） | Must | 人工补充 |
| F-12 | 每个用户有信用分（初始100分），根据评价和行为动态调整 | Must | 人工补充 |
| F-13 | 信用分低于60分无法发布任务 | Should | 人工补充 |
| F-14 | 用户可查看他人的信用分和评价记录 | Could | AI生成+人工修改（原仅AI提出查看信用分，人工补充评价记录） |

### 3.4 校内定位模块

| 编号 | 需求描述 | 优先级 | 来源 |
|------|----------|--------|------|
| F-15 | 任务按距离发布者宿舍楼/教学楼排序 | Should | 人工补充 |
| F-16 | 用户可设置常用位置（宿舍、教学楼、食堂） | Could | 人工补充 |

### 3.5 组队匹配模块

| 编号 | 需求描述 | 优先级 | 来源 |
|------|----------|--------|------|
| F-17 | 用户可发布组队需求（比赛、学习小组、拼单） | Should | AI生成+人工修改（人工补充拼单类型） |
| F-18 | 系统可推荐匹配的队友（按专业、兴趣、年级） | Could | 人工补充 |
| F-19 | 支持组队群聊功能 | Could | AI生成 |

### 3.6 隐私与安全模块

| 编号 | 需求描述 | 优先级 | 来源 |
|------|----------|--------|------|
| F-20 | 聊天中使用虚拟号码，保护双方隐私 | Should | 人工补充 |
| F-21 | 支持匿名发布任务（仅对管理员可见真实身份） | Could | 人工补充 |
| F-22 | 违规任务可举报，管理员审核后处理 | Must | AI生成+人工修改（人工补充管理员审核流程） |

### 3.7 二手交易模块

| 编号 | 需求描述 | 优先级 | 来源 |
|------|----------|--------|------|
| F-23 | 用户可发布二手物品（图文、价格、新旧程度） | Should | AI生成 |
| F-24 | 支持交易双方在线沟通和约定面交 | Should | AI生成 |
| F-25 | 完成交易后双方确认，计入信用分 | Could | 人工补充 |

### 3.8 消息通知模块

| 编号 | 需求描述 | 优先级 | 来源 |
|------|----------|--------|------|
| F-26 | 接单、取消、完成等状态变更时发送模板消息 | Must | AI生成 |
| F-27 | 任务到期前1小时提醒发布者 | Could | AI生成+人工修改（原为24小时，改为1小时） |

## 4. 非功能需求

| 编号 | 需求描述 | 优先级 | 来源 |
|------|----------|--------|------|
| NF-01 | 页面加载时间 ≤ 2秒 | Must | AI生成 |
| NF-02 | 支持至少1000人同时在线 | Should | AI生成 |
| NF-03 | 用户敏感信息（手机号、学号）加密存储 | Must | 人工补充 |
| NF-04 | 信用分规则公开透明，支持用户申诉 | Should | 人工补充 |
| NF-05 | 系统可用性 ≥ 99.5% | Must | AI生成 |
| NF-06 | 操作流程不超过3步完成核心任务（发布/接单） | Should | 人工补充 |

## 5. 需求追踪矩阵

| 需求编号 | 对应用例 |

| F-11 ~ F-14 | 评价、查看信用分 |
| F-15, F-16 | 附近任务 |
| F-17 ~ F-19 | 组队匹配 |
| F-20 ~ F-22 | 聊天、举报 |
| F-23 ~ F-25 | 二手交易 |
