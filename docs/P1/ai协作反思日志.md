## 2. AI 助力分析（Q1）

**本阶段 AI 最大的贡献是：**

快速生成结构化的文档框架和模板，大幅减少了从零搭建文档结构的时间。特别是在需求规格说明书、用户故事、用例图等标准化输出上，AI能够按照IEEE830等规范格式自动生成内容框架，让团队可以专注于填充真实调研数据和修正细节。

**估计节省时间：约 8-10 小时**

## 3. AI 误导分析（Q2）

### 发现的 AI 输出问题：

**问题1：AI捏造了不存在的需求**

- **具体描述**：AI生成的需求中包含“跨校互助”、“全球校园联盟”等功能
- **如何发现**：通过用户访谈发现，所有受访者均表示不需要跨校功能，校内互助已足够
- **如何修正**：删除所有跨校相关需求，将系统范围限定为本校

**问题2：AI遗漏了关键的信任机制**

- **具体描述**：AI生成的需求中完全没有信用分、评价体系、爽约惩罚等机制
- **如何发现**：访谈中多位用户提到担心被骗、希望有评价系统约束行为
- **如何修正**：人工补充了完整的信用与评价模块（F-11至F-14），包含信用分、互评、黑名单等

**问题3：AI表述存在歧义**

- **具体描述**：AI生成“系统应自动匹配任务”，用户理解为强制分配任务
- **如何发现**：访谈中用户反馈不希望被强制分配，希望有选择权
- **如何修正**：将表述改为“任务智能推荐（非强制）”，强调推荐而非分配

**问题4：AI遗漏了校内地理相关功能**

- **具体描述**：AI没有考虑校内定位、距离排序等功能
- **如何发现**：访谈中用户希望就近接单，节省时间
- **如何修正**：人工补充校内定位模块（F-15、F-16），支持按距离排序

## 4. Prompt 改进计划（Q3）

**本阶段使用的 Prompt 策略存在的问题：**

1. **Prompt过于笼统**：只说了“按IEEE830格式”，没有明确要求包含信任机制、地理位置等校园特有场景
2. **没有约束AI不要捏造**：AI自由发挥生成了跨校等不切实际的功能
3. **没有要求AI标注不确定项**：AI把所有需求都写得很有信心，没有主动提示哪些内容需要人工验证

**下阶段计划采用的改进措施：**

1. **增加场景约束**：在Prompt中明确“仅限校内场景”、“需要考虑学生之间的信任问题”
2. **禁止捏造**：增加指令“不要生成无法验证的功能”、“如果不确定，请标注[需验证]”
3. **分步生成**：不再一次性生成全部内容，而是分模块生成，每步人工确认后再继续
4. **提供示例**：在Prompt中给出信用分、评价系统的示例，引导AI输出类似内容

**优化后的Prompt示例（供下阶段使用）：**

请为校园互助平台生成需求规格说明书，要求：

仅限校内场景，不考虑跨校

必须包含：用户认证、信任机制（信用分/评价）、地理位置

不要捏造功能，不确定的内容请标注[需验证]

按IEEE830格式输出，每条需求标注优先级

## 5. 本阶段的核心工程判断

**决策内容：**

确定信用分体系的核心规则——初始100分，完成任务双方各+1分，爽约扣5分，信用分低于60分无法发布任务。

**为什么 AI 无法做这个决策：**

1. **需要权衡用户体验与约束力度**：扣分太多会劝退用户，太少没有约束力。这个平衡点需要结合对学生群体的理解和团队资源判断
2. **涉及后续开发成本**：信用分规则会影响数据库设计、定时任务、前端展示等多个模块，AI无法评估实现成本
3. **没有真实数据支撑**：60分的阈值是团队基于对校园场景的理解做的经验判断，AI缺乏对真实用户行为的认知
4. **需要与产品定位对齐**：团队希望平台强调“互帮互助”氛围而非纯粹交易，因此信用分规则需要鼓励良性行为而非单纯惩罚，这种价值观判断AI无法替代
